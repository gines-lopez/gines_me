## Project overview

Personal blog for gines.me, built on Astro's official blog starter template. Content is Markdown/MDX posts under `src/content/blog/`, rendered through content collections.

## Reglas del proyecto

- Este sitio se despliega solo. Al hacer push a `main`, GitHub Actions compila y genera la rama `production`. NUNCA edites la rama `production` a mano ni la menciones en commits.
- La web se sirve desde un servidor Plesk que clona la rama `production`.
- Todo el contenido va en español de España.
- Prioridad absoluta: velocidad y SEO. Nada de JavaScript en el cliente salvo que sea imprescindible.
- Toda página nueva debe llevar `title` único, `meta description` y `canonical`.
- El sitio es https://gines.me

## Commands

```
npm run dev              # start dev server at localhost:4321
npm run build            # type-check content collections and build to ./dist/
npm run preview          # preview the production build locally
npm run astro check      # type-check .astro files and content schemas
npm run astro -- --help  # Astro CLI help
```

There is no lint/format tooling or test suite configured in this repo.

When starting the dev server, use background mode:

```
astro dev --background
```

Manage the background server with `astro dev stop`, `astro dev status`, and `astro dev logs`.

## Architecture

- **Content collections**: blog posts live at `src/content/blog/**/*.{md,mdx}` and are loaded via the `glob` loader defined in `src/content.config.ts`. The Zod schema there (`title`, `description`, `pubDate`, `updatedDate?`, `heroImage?`) is the source of truth for post frontmatter — new required/optional fields must be added there first.
- **Routing**: `src/pages/blog/index.astro` lists posts (via `getCollection('blog')`); `src/pages/blog/[...slug].astro` is the dynamic per-post route rendered through the `BlogPost` layout in `src/layouts/BlogPost.astro`.
- **Site-wide constants**: `SITE_TITLE` and `SITE_DESCRIPTION` live in `src/consts.ts` and are imported wherever page metadata / headers need them, rather than being hardcoded per page.
- **Fonts**: `Inter` and `Roboto` are registered in `astro.config.mjs` via the `fonts` integration using `fontProviders.google()` (self-hosted at build time, no runtime request to Google). CSS exposes them as `--font-heading` (Inter) and `--font-body` (Roboto) in `src/styles/landing.css`; `--font-mono` stays a system stack reserved for `code`/`pre` markdown rendering only.
- **Integrations**: `@astrojs/mdx` (MDX post support), `@astrojs/sitemap` (auto sitemap), `@astrojs/rss` (feed generated by `src/pages/rss.xml.js`). `site` in `astro.config.mjs` is set to `https://gines.me` and is required for sitemap/RSS/canonical URLs to resolve correctly.
- **Static hosting file**: `public/.htaccess` handles the deployed site's HTTPS/non-www redirect and cache headers — the production target is Apache-based shared hosting, not a platform like Vercel/Netlify.
- **CSS cascade gotcha**: the homepage hero's plain `h1` selector in `landing.css` sets `max-width: 20ch`. `h1.section-title` / `h2.section-title` — the page-title class used on `sobre-mi.astro`, `uso-ia-en-el-proyecto.astro`, `blog/index.astro`, `contacto.astro`, `blog/tag/[tag].astro` — didn't reset `max-width`, so that 20ch limit silently bled in and forced titles onto two lines regardless of font-size. The `.section-title` rule now sets `max-width: none` explicitly; keep that override if the hero's `h1` rule changes.

## Convenciones de contenido

- **Blockquotes**: `landing.css` estiliza `blockquote`/`cite` globalmente (borde izquierdo en `--accent`, cursiva, `cite` en gris no cursiva). No hay reset propio en `BlogPost.astro`, así que el estilo aplica igual en posts del blog y en páginas sueltas — no hace falta repetirlo por página.
- **Citas con fuente**: el texto de una cita no se enlaza directamente. El patrón es nota a pie de página: `<sup><a href="#fn-x" id="fnref-x">n</a></sup>` junto al texto citado, y al final del contenido un `<ol class="footnotes">` con `<li id="fn-x">` que lleva el enlace real y un `↩` de vuelta a `#fnref-x`. Ver `src/pages/uso-ia-en-el-proyecto.astro` como referencia de implementación (incluye el `<style>` scoped para `sup a` y `.footnotes`).
- **Sección oscura deliberada**: la sección `#historia` ("¿Quién es Ginés López?") en `index.astro` tiene fondo negro y texto blanco a propósito (regla `#historia` en `landing.css`), distinta al resto del sitio que es claro. No es un bug de `prefers-color-scheme` ni hay que "corregirlo" — es un bloque de diseño fijo e independiente del tema.

## Deployment

`.github/workflows/deploy.yml` runs on every push to `main`: it builds the site, then force-replaces the contents of the `production` branch with the contents of `dist/` (via an orphan-branch checkout + `git rm -rf` + copy + commit). The `production` branch is a build artifact, not a development branch — never commit source changes directly to it, and treat pushes to `main` as effectively triggering a live deploy.
